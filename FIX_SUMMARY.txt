  ✅ FIXED: MySQL Error 1824 - Failed to open the referenced table
================================================================================

PROBLEM:
--------
Error 1824 (HY000): Failed to open the referenced table 'categories'

The Products table was being created BEFORE the Categories table, 
causing the foreign key constraint to fail.


SOLUTION:
---------
Fixed table creation order to ensure parent tables are created first.

┌─────────────────────────────────────────────────────────────────┐
│  BEFORE (❌ Wrong Order)                                        │
├─────────────────────────────────────────────────────────────────┤
│  db.AutoMigrate(&User{}, &Category{}, &Product{})              │
│                                                                 │
│  Sometimes creates:                                             │
│  1. Users    ✓                                                  │
│  2. Products ✗ (tries to FK to Categories - doesn't exist!)    │
│  3. Category ✓                                                  │
│                                                                 │
│  Result: ERROR 1824                                             │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  AFTER (✅ Correct Order)                                       │
├─────────────────────────────────────────────────────────────────┤
│  // Step 1: Users (no FK dependencies)                          │
│  db.AutoMigrate(&User{})                                        │
│                                                                 │
│  // Step 2: Categories (no FK dependencies)                     │
│  db.AutoMigrate(&Category{})                                    │
│                                                                 │
│  // Step 3: Products (FK to Categories - now exists!)           │
│  db.AutoMigrate(&Product{})                                     │
│                                                                 │
│  Result: ✓ All tables created successfully                      │
└─────────────────────────────────────────────────────────────────┘

HOW TO USE:
-----------

Option 1: Automatic (Recommended)
----------------------------------
Just start the app - migrations run automatically in correct order:

  docker-compose up -d
  sleep 30
  docker-compose exec api go run /root/scripts/seed.go

Option 2: Manual SQL Migration
-------------------------------
Run SQL script directly:

  mysql -u root -p greenlight_db < migrations/001_create_tables.sql

Option 3: Reset Everything
---------------------------
Clean slate (deletes all data):

  # Docker
  docker-compose down -v
  docker-compose up -d

  # Local (Unix)
  ./scripts/reset_db.sh

  # Local (Windows)
  scripts\reset_db.bat


VERIFICATION:
-------------

Check if tables were created:

  docker-compose exec db mysql -u root -proot -e "USE greenlight_db; SHOW TABLES;"

Expected output:
  +-------------------------+
  | Tables_in_greenlight_db |
  +-------------------------+
  | categories              |
  | products                |
  | users                   |
  +-------------------------+

Check foreign key:

  docker-compose exec db mysql -u root -proot greenlight_db -e "
    SELECT CONSTRAINT_NAME, TABLE_NAME, REFERENCED_TABLE_NAME 
    FROM INFORMATION_SCHEMA.KEY_COLUMN_USAGE 
    WHERE TABLE_SCHEMA='greenlight_db' AND REFERENCED_TABLE_NAME IS NOT NULL;"

  +----------------------+------------+-----------------------+

  +----------------------+------------+-----------------------+
